# Evidenza — Preparazione dell'ambiente e metodo di lavoro

## Ambiente verificato

La postazione usa **Fedora Linux 44 (KDE Plasma) nativo**, non Windows con WSL 2/Ubuntu come
previsto dal materiale standard del corso. L'obiettivo didattico dell'UD01 — disporre di un

## Workflow completato

Il materiale del corso è stato ottenuto clonando il repository pubblico in `~/workspace/`.
Dopo aver verificato gli strumenti già presenti, è stato creato il repository personale
pubblico `azure-devops-lab` su GitHub e clonato nella stessa cartella `~/workspace/`. È stato
copiato un `.gitignore` adatto ai moduli successivi del corso e create le cartelle `evidenze/`
e `laboratori/UD01/`. Prima di ogni commit, `git status --short` ha mostrato i file non
tracciati; `git add` ha selezionato soltanto i file richiesti per questa unità, verificato con
un secondo `git status` e con `git diff --cached` prima di procedere. Il commit locale è stato
creato con `git commit` e inviato al repository remoto con `git push`; `git log -1 --oneline`
ha confermato hash e messaggio del commit pubblicato.

Prima verifica diagnostica: `git status --short` prima di ogni `git add`, per controllare
esattamente quali file sarebbero entrati nel commit.

successo tramite il flusso `--use-device-code`: la subscription risulta attiva. Subscription
ID e tenant ID non vengono riportati per policy di sicurezza del repository pubblico.
